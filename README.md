# NotifyBox

根据 Android 通知管理初版设计实现的独立源码工程，版本 0.1.0。初版沿用目录名 NotifyBox，包名为 `io.github.notifybox`，目标为 Android 13 / 小米 13；最低 Android 8.0。

## 已实现

- 规则列表、编辑、启停；应用图标与关键词标签、匹配方式下拉选择、可展开设置及底部保存栏；包名与系统用户标识分别匹配。整体 UI 采用到点啦的浅蓝紫背景、藏蓝文字、衬线标题与圆角卡片。
- 标题/正文包含、不包含、任一、全部、正则及大小写选项；多动作和多规则命中。
- 通知到达、内容更新、移除记录；筛选、详情、从记录建规则和只读试跑。
- 延迟消除按 key 与修订核对，合并最早截止时间；重复内容不重置；规则关闭/删除后不执行对应消除。
- 通用 HTTPS GET/POST、JSON/纯文本请求体、请求头及模板；Telegram POST JSON。
- Room 持久转发队列、去重、网络约束、限流延后、持续退避重试、失败通知、显式测试与手动重试/暂停；重试更新同一条记录。
- Keystore AES-GCM 加密完整转发配置和排队请求；禁止云备份及设备迁移备份。
- JSON 导入预览、保守的旧格式适配、只新增导入；完整导出规则与转发凭证到预设 SAF 文件夹。
- 通知访问、通知提醒、电池及后台限制检测；厂商自启动等项目支持手动确认；HTTP/SOCKS 代理配置。
- 独立前台服务、开机恢复、监听重连、持久化延迟截止时间；通知和转发记录每页 20 条。

新规则默认启用，未选择应用时不处理任何通知；消除动作默认 5 秒并包括常驻通知。导入规则仍默认关闭。没有预置真实凭证，也不会导入后自动发送。

## 在 Android Studio 使用

1. 打开本目录，Gradle JDK 可使用 AS 自带的 JDK 21，编译目标保持 Java 17；使用 Android SDK 35 / Build Tools 35.0.0。
2. Gradle Sync。工程使用官方 Gradle Wrapper 8.11.1，首次同步由 AS 下载依赖；不要把手机的 Telegram Token 写入构建配置。
3. 在设备安装后，到“设置 → 管理通知访问权限”主动授权 NotifyBox；根据需要允许自启动及取消电池限制。
4. 在“转发”配置目的地，在“规则”配置匹配和动作。先用历史通知试跑，确认后启用。
5. 需要正式 APK 时，在 AS 中选择 Generate Signed APK，选择 release 和自己的长期签名密钥。保持包名和签名不变才能覆盖升级。源码没有内置签名密钥。

依赖已固定：AGP 8.9.2、Kotlin 2.1.20、Compose BOM 2025.04.01、Room 2.7.1、WorkManager 2.10.1、Navigation Compose 2.9.0。采用固定的稳定版本组合，没有自动跟随最新版本。
[AGP 8.9 的官方兼容说明](https://developer.android.com/build/releases/agp-8-9-0-release-notes)要求 Gradle 8.11.1、最低 JDK 17 和 SDK 35；[Kotlin 2.1.20 说明](https://kotlinlang.org/docs/whatsnew2120.html)包含 Gradle 兼容信息。

## 工程结构

- `core/`：模型、校验、RE2 规则引擎、模板、消除计划、导入适配、网络结果策略和单元测试。
- `app/.../data/`：Room、Keystore、队列与导入导出。
- `app/.../listener/`：通知采集、串行处理与系统消除核对。
- `app/.../worker/`：WorkManager 发送及记录保留。
- `app/.../ui/`：四个入口、编辑、试跑、Navigation 返回保护及 AS Preview。
- `docs/`：规则格式及验证清单；`examples/`：无凭证的本 App 格式示例。
- `.private/`：本次隔离的静态语法检查工具，不属于源码或交付产物，已被忽略。

## 已知边界

- 没有原始 FilterBox 导出样本，旧格式只能接受可识别的列表及显式字段。未知应用编码、限制和枚举会阻止该规则启用，需编辑确认。示例和测试夹具不是用户真实导出，不能证明四条旧规则已无损迁移。
- “全部消除”忽略残留文本，“部分消除”的字段语义仍待确认；WHEN 格式、dismissed_notify 和旧去重算法不会猜测还原。
- user=999 能否收到分身通知、常驻通知能否消除、锁屏和省电状态下的调度，需要真机验证。
- 监听重连时只恢复内容仍匹配的延迟任务，截止时间不重置；漏收的活跃通知按系统发布时间计算剩余延迟。最近任务划掉、锁屏、省电、进程终止及重启恢复仍需小米真机验证；系统“强行停止”后不能承诺后台继续执行。
- 网络故障默认持续重试，退避间隔上限 30 分钟，服务端要求更久时遵守。超时/中断后重发可能重复接收；关闭持续重试后，明确未发送的失败最多尝试 3 次，结果未知需手动重试。认证/配置错误不循环重试。
- 目标服务仅允许 HTTPS，不跟随重定向；代理可使用系统 VPN 或在设置中指定 HTTP/SOCKS 地址。代理设置每次发送读取，修改节点后无需重建队列。
- 记录与转发页从数据库每次取 20 条，筛选后分页。默认保留 7 天（1—90 天可调），通知/完成任务分别最多 10000 条、动作最多 50000 条，定期清理；待处理转发上限 1000 条。采集队列上限 512，过载会在设置中报告丢失事件。
- 凭证编辑草稿仅留在页面内存，不进入系统保存状态；进程重建时重新读取已加密保存的配置。
- 前台服务发布持续状态通知，转发失败使用单条更新提醒；需允许通知提醒权限。不请求短信读取或无障碍权限。
